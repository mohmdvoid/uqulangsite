What uqulang is

uqulang is a statically typed, ahead-of-time compiled language for systems work: operating system components, embedded firmware, codecs, databases, game engines, and the layer underneath applications. It produces native binaries with no runtime and no garbage collector, and it interoperates with C at the ABI level rather than through a binding layer. It is licensed to universities and research institutions for teaching and research use.

It borrows deliberately. Syntax, modules, optionals and pattern matching come from the Swift tradition. Pointers, explicit layout, manual lifetimes and the compilation model come from C. Nothing in the language is there to be novel — every feature has to pay for itself in code that ships.

What uqulang is not

  • Not a scripting language. There is no REPL-first workflow and no dynamic typing. Everything is checked before it runs.
  • Not a borrow checker. Lifetimes are scope-based and explicit. The compiler catches use-after-move and double-free, but it does not attempt to prove every aliasing property.
  • Not finished. 0.1 is a preview. Generics over constant values, async I/O and the package registry are designed but unshipped.

Stability and versioning

Until 1.0, the language may change in a breaking way in any minor release. Each release ships a written migration note, and uqu fix applies the mechanical parts of a migration to your source.

AreaStatus at 0.1
Core syntax, control flow, functionsStable in practice; changes are rare and announced
Traits and genericsEvolving; expect refinement before 1.0
Ownership and moveEvolving
Standard library layoutUnstable; modules may be renamed or split
C ABI interopStable by definition — it follows the platform ABI
Package registryNot shipped

How to read these docs

Code samples are complete programs unless a comment says otherwise. Shell samples show the prompt as $; copying a shell block strips prompts so you can paste it directly. Anything the compiler does not yet implement is labelled planned in place, never quietly implied.

Getting help

Defects, incorrect diagnostics and documentation errors go to the support portal through your institution’s named contacts. Response targets, and how feature requests reach the roadmap, are on the licensing page.
