## What it means {#meaning}

Integer types do not convert into one another on their own, in either
direction. `i32` and `i64` are different types, and so are `i32` and `u32`.

## An example that triggers it {#example}

```uqulang
let a: i32 = 7
let b: i64 = 1_000
let c = a + b       // error[E0202]: no implicit conversion from i32 to i64
```

## How to fix it {#fix}

Convert the narrower value at the point where the widths meet:

```uqulang
let c = i64(a) + b
```

Converting the other way is also explicit, and can fail — which is why it is a
checked conversion rather than a cast:

```uqulang
let narrowed = try i32.from(b)      // throws if b does not fit
```

## Why the rule exists {#why}

Implicit integer promotion is the source of a whole family of C bugs that only
appear at a particular width, on a particular platform, with a particular input.
Writing the conversion down costs one line and makes the width visible at the
place where it matters.
