    Compiler error

    E0201 — type mismatch

    What it means

    The expression is well formed but has the wrong type for where it appears. The message names the type required by the position and the type the expression actually has, in that order.

    An example that triggers it

    func area(w: f32, h: f32) -> f32 {
    return w * h
}

let side = 3            // inferred i32
let a = area(side, side)   // error[E0201]: expected f32, found i32

    How to fix it

    Convert explicitly, or bind with the type you meant:

    let side: f32 = 3.0
let a = area(side, side)

    Why the rule exists

    There are no implicit numeric conversions in uqulang. A widening conversion is cheap but not free, and a narrowing one can silently lose information — so both are written down where they happen. See E0202 for the numeric case specifically.
