    Compiler error

    E0101 — use of moved value

    What it means

    Every heap value has exactly one owner. move transfers that ownership, and the binding it came from is dead afterwards — reading it would alias memory that somebody else is now responsible for freeing.

    An example that triggers it

    src/main.uqu
    func main() throws {
    var buf = try Buffer.with_capacity(64)
    let owned = move buf        // ownership transfers to `owned`

    io.write(buf.bytes())       // error[E0101]: use of moved value `buf`
}

    How to fix it

    Use the new owner:

        io.write(owned.bytes())

    Or do not move at all. If the callee only needs to read the value, pass a pointer and leave ownership where it is:

        inspect(&buf)               // borrows; `buf` is still yours afterwards

    Why the rule exists

    This is the check that makes manual memory management teachable. In C the same program compiles and then fails at run time, sometimes only under load. Here it cannot get past the compiler, and the message names the line that moved the value as well as the line that used it.
